# Neovim vim.pack Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Lazy.nvim with an eager native vim.pack setup for a real-world evaluation branch and document the former trigger-loaded plugins and trial results.

**Architecture:** Register the existing plugin set with vim.pack before utils/core load, then configure plugins through ordinary Lua setup while preserving current behavior. Replace Lazy-specific consumer integrations, use vim.pack's native lockfile/update mechanism, and track former triggers plus trial results in the ai-brain note.

**Tech Stack:** Neovim Lua, built-in `vim.pack`, Git; current trial environment has Neovim `v0.13.0-dev-1531+g48864161cd`.

**Spec:** `docs/superpowers/specs/2026-10-05-neovim-vim-pack-migration-design.md`

## Global Constraints

- Load configured plugins eagerly during startup; do not reproduce event, command, filetype, or key-triggered loading.
- Use vim.pack's native lockfile and update flow; `lazy-lock.json` is no longer the active lockfile for this branch.
- Translate only build steps needed by existing plugins, using `PackChanged` hooks where appropriate.
- Retain local development overrides only where they remain useful and fit the native setup.
- The trial requires a Neovim version/build that provides `vim.pack`.
- Preserve the existing plugin set and behavior unrelated to Lazy; avoid unrelated upgrades, removals, or refactors.
- Do not push the branch or decide the long-term plugin manager as part of implementation.

## Review Focus

- **Fresh data directory:** first startup must install plugins and continue only once plugins are available; exercise with a temporary `XDG_DATA_HOME`.
- **Local development plugin absent:** source fallback must still resolve the configured Git plugin; verify the local override/fallback behavior.
- **Conditional plugin selection:** the existing `HOME`-based Wakatime condition must remain effective; inspect the generated source set under both conditions where practical.
- **Build hook path and repeatability:** CodeCompanion's patch must target the vim.pack install path and not be applied unexpectedly on ordinary startup; verify install/update hook behavior.
- **Unsupported Neovim:** startup should fail clearly when `vim.pack` is unavailable rather than error later in unrelated setup; verify the guard/message.
